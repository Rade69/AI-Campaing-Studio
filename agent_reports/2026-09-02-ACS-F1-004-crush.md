## Design decisions (dokumentovano)

- **`domain/visual/enums.py` — additive only.** Added `ImageTreatment`
  (`NONE`/`BORDER`/`SHADOW`/`ROUNDED`), `LogoRule` (`SHOW`/`HIDE`),
  `CtaRule` (`SHOW`/`HIDE`) as NEW classes. No existing enum value changed.
  These values are reasonable assumptions (contract does not specify them);
  the A3 `CampaignVisualSystem` dataclass stays `str` for those fields — this
  schema validates the string against the enum before it reaches a mapper.
- **`campaign_plan_output.py`** — `role` typed as `CampaignRole` (imported
  from `domain.campaign.roles`), `topic` `min_length=1`, order unique +
  contiguous 1-based via `model_validator`. Item count is enforced by
  `validate_campaign_plan_output(data, content_piece_count)` (passed as a
  validation parameter, not hardcoded).
- **`revision_output.py`** — partial-update semantics via Pydantic
  `model_fields_set` (exposed as `changed_fields`), distinguishing "field not
  sent" from "field explicitly empty". Documented in docstring.
- **`social_post_generation_output.py`** — `claims[].type` typed as
  `ClaimType` (imported from `domain.content.enums`), not `str`.
- **`visual_direction_output.py`** — all enum-typed attributes use real
  domain enums (`LayoutPrimitive`, `HeadlineScale`, `Alignment`,
  `ImagePosition`, `HeadlinePosition`, `Overlay`, `LogoPosition`, `CtaStyle`,
  `ImageTreatment`, `LogoRule`, `CtaRule`); `format` is `str` (data-driven
  registry code). Arbitrary LLM strings are rejected at parse time.
