## Implementation notes — non-obvious decisions

1. **No code change outside `allowed_paths` and the contract scope.**
   The `if __name__ == "__main__": raise SystemExit(main())` block in
   `validate_resources.py` was already present in the pre-task version
   on `main`; the diff against the pre-task file shows it as a
   **context** line, not an addition. My earlier evidence-report draft
   incorrectly claimed I had to restore a missing `__main__` block;
   that claim was wrong and is corrected here. The real reason the
   adversarial reproducer (ADV 1.b) works is simply that `main()` now
   returns `1` when `validate_platforms` reports the duplicate
   platform code — that return value is propagated by the existing
   `__main__` block, so the shell exit code is `1` and the contract's
   "exit 1 on failure" requirement is satisfied without any scaffolding
   change. The earlier "silent exit 0" observation during local
   testing was an artefact of the PowerShell `2>&1 | Out-String`
   pipeline buffering, not of any code defect.

2. **`generate_phase0_gate_report.py` does NOT touch `main.py` /
   `bootstrap.py` / `AppSettings` to thread a `data_dir_override`
   env var.** It uses the existing constructor parameter
   (`AppPaths(data_dir_override=...)`) inside the same Python process
   — same as the CI inline `python -` step. This keeps
   `forbidden_paths` intact and matches the contract's
   "provjeri kako AppSettings/AppPaths već podržavaju override"
   instruction.

3. **Health-check JSON key remapping.** `bootstrap.run_health_check`
   returns the key `"database"`; the gate report's P0.27 schema (plan
   §35) requires `"database_connection"`. The mapping is explicit in
   `_check_registries_with_bootstrap` and documented inline. Renaming
   the runtime key would have been a cross-task contract change.

4. **Anti-recursion guard for the e2e test.** The
   `test_gate_report_against_current_repo_passes` e2e test invokes
   the real gate report, which itself invokes `pytest -q` as one of
   its 17 checks. To prevent infinite recursion, the gate report sets
   `ACS_GATE_REPORT_RUNNING=1` for its pytest subprocess, and both
   the gate report e2e test and the scanner e2e test skip themselves
   when that env var is set. This is a real concern: without the
   guard, running `pytest -q` from the worktree would recurse forever
   (proven during the work — I had to add the guard after the first
   pytest run hung indefinitely).

5. **Secret scanner scope.** The contract's "isključi `*.md`
   dokumentaciju i `agent_reports/`" instruction is implemented as a
   top-level extension + path-component check in `_is_scannable`.
   `scripts/check_no_secrets.py` is also excluded by exact filename
   so the pattern definitions inside it never self-match.

6. **Placeholder filter is substring-based, not equality-based.**
   `validate_resources._is_placeholder` and
   `check_no_secrets._is_placeholder` use the same shared substring
   vocabulary (`example`, `your-key`, `redacted`, `placeholder`, …)
   so a value like `sk-EXAMPLEKEYEXAMPLEKEY` is filtered out in both
   tools. Without this, a single literal placeholder value would
   pass one tool and fail the other.

7. **Bypass note for Codex review (per contract §Review focus — Codex).**
   The current scanner does not handle: multi-line concatenated
   secrets, base64-encoded secrets, secrets split across two string
   literals (`"sk-" + "abc..."`). The contract calls these "vjerovatno
   van P0 scope-a" — I agree. The four patterns cover the realistic
   accidental-leak shapes (assignment, JSON dict, env-style
   `KEY=VALUE`, HTTP `Authorization: Bearer`).
