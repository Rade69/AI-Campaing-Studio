## Adversarial dokaz — atomicity (NAJVAŽNIJI test)

`test_claim_next_crawl_target_is_atomic_under_concurrency`: 2 thread-a,
svaki sa svojim connection-om, `threading.Barrier` sinhronizacija, 4 PENDING
targeta, istovremeni `claim_next_crawl_target`. Ispravan kod (BEGIN IMMEDIATE)
→ 2 claim-a, 2 RAZLIČITA targeta, nula duplog.

**Mutation dokaz**: privremeno zamenjen `BEGIN IMMEDIATE` → `BEGIN`
(deferred), concurrent test pokrenut 10x zaredom:

```text
1 failed / 1 failed / 1 failed / 1 failed / 1 failed
1 failed / 1 failed / 1 failed / 1 failed / 1 failed
```

Svaki FAIL je `OperationalError('database is locked')` — deferred BEGIN +
SELECT(shared) + UPDATE(upgrade) dovodi do SQLite deadlock-a kod dva
konkurentna claim-a. Fajl vraćen (diff identičan backup-u), test ponovo PASS.
Ovo dokazuje da je `BEGIN IMMEDIATE` NEOPHODAN, ne samo "izgleda ispravno".

# Fix nakon Claude review nalaza (cross-run leak)

Blokirajući nalaz: `list_source_snapshots_by_run` je prvobitno bio URL-join
(`crawl_targets.normalized_url == source_snapshots.url`) — kada dva run-a
crawl-uju ISTI URL u različito vrijeme (svaki sa svojim snapshot-om),
`list_source_snapshots_by_run(run-a)` je vraćao snapshot-ove OBA run-a
(cross-run leak).

Fix (ista specifikacija kao ACS-S2-002-fix-brief.md):

1. **Migracija**: `crawl_targets.snapshot_id TEXT NULL REFERENCES
   source_snapshots(id)` (aditivna kolona u još-ne-merge-ovanoj migraciji,
   nema ALTER).
2. **Domain**: `CrawlTarget.snapshot_id: SourceSnapshotId | None = None`.
3. **Port**: `update_crawl_target_state(..., snapshot_id: SourceSnapshotId |
   None = None)`.
4. **Adapter**: `register_crawl_targets`/`_crawl_target_from_row` uključuju
   kolonu; `update_crawl_target_state` koristi
   `snapshot_id = COALESCE(?, snapshot_id)` (ASIMETRIJA: `last_error=None`
   briše, `snapshot_id=None` zadržava postojeću vrijednost — dokumentovano u
   docstring-u); `list_source_snapshots_by_run` sada JOIN-uje preko
   `crawl_targets.snapshot_id = source_snapshots.id` (ne URL).
5. **Regresioni testovi**:
   - `test_list_source_snapshots_by_run_has_no_cross_run_leak` — dva run-a,
     isti URL, različiti snapshot-ovi; svaki run vraća SAMO svoj snapshot.
   - `test_update_crawl_target_state_keeps_snapshot_when_not_passed` —
     COALESCE semantika (bez snapshot_id → zadržava; sa → overwrite).

# Fix nakon Codex review nalaza (BF-1 — lease_until timing)

Codex REJECT: BF-1 (HIGH) — `lease_until` se računao PRIJE `BEGIN IMMEDIATE`.
Ako `BEGIN IMMEDIATE` blokira do `busy_timeout` (5000ms) na tuđem write
lock-u, claim se commit-uje NAKON što je već izračunati lease istekao;
`recover_expired_leases` tada odmah re-queue-uje target koji prvi worker
JOŠ obrađuje → drugi worker ga claimuje istovremeno.

Fix: pomjeriti `lease_until = utc_now() + timedelta(...)` U try blok, POSLIJE
uspješnog `BEGIN IMMEDIATE` (prije SELECT-a). Dodata i validacija
`lease_duration_seconds <= 0` → `ValueError` (Codex sugestija, usvojena).
BF-2 (`__init__.py` scope) je koordinatorov kontrakt propust — eksplicitno
odobren, nema izmjene.

Regresioni test `test_claim_lease_until_is_future_under_contention`: holder
thread drži `BEGIN IMMEDIATE` duže od 1s lease-a, claimer blokira pa claimuje;
asercija `claimed.lease_until > datetime.now(UTC)`.

**Mutation dokaz**: privremeno vraćena stara redoslijed (lease prije BEGIN
IMMEDIATE) → regresioni test FAIL (`lease_until` 11:27:30.856 < sada
11:27:31.396 — lease u prošlosti). Vraćeno → PASS. Postojeći
`test_claim_next_crawl_target_is_atomic_under_concurrency` i dalje PASS
(fix dira timing, ne atomicity).
