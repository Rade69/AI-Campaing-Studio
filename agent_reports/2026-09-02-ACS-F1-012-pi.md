## Implementation summary

### `resources/claim_rules/default_v1.yaml`

Data-driven rules with exactly the plan §36 initial lists: `prohibited_terms`
(9 terms) and `currency_symbols` (`KM/BAM/EUR/€/RSD`). Extensible by adding a
string — no code change required.

### `claim_linter.py`

`ClaimRules` (frozen) + `load_claim_rules(path)` (reads YAML) + `lint_claim`:
- Prohibited/risky term (case-insensitive substring) → `PROHIBITED` +
  `prohibited-claim` reason — overrides any prior status including
  `VERIFIED_BY_FACT`.
- Numeric signals only for claims that are NOT already `VERIFIED_BY_FACT`
  (checked in order price → percent → duration → date → generic number),
  escalating to `UNSUPPORTED` with the matching reason code.
- Otherwise the claim is returned unchanged.

### `derive_content_status.py`

Pure function: any `PROHIBITED` or `UNSUPPORTED` → `NEEDS_REVIEW`, else
`DRAFT`. Never `APPROVED`.

### `generate_social_post.py` rewiring

Replaced the interim status block with:
`validate_claim` → `load_claim_rules(_CLAIM_RULES_PATH)` → `lint_claim` per
claim → `derive_content_status(claims)`. `__init__` signature unchanged.
`_CLAIM_RULES_PATH` is a module constant resolved relative to the file
(`parents[4]/resources/claim_rules/default_v1.yaml`).
