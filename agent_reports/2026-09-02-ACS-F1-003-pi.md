## Implementation summary

### `application/schemas/brand_fixture.py` (Pydantic boundary)

`BrandFixtureSchema` with nested `BrandInfoSchema`, `BrandVoiceSchema`,
`AudienceSchema`, `ServiceDefinitionSchema`, `RestrictionSchema`,
`VisualIdentitySchema`, `SourceReferenceSchema`, `FactSchema` — each mirroring
the corresponding domain value-object fields. `default_content_language_context`
reuses the existing `ContentLanguageContext` (no parallel language schema).

Validation:
- `facts` must be non-empty (`model_validator`).
- `logical_fact_id` unique within a fixture (`model_validator`).
- `source_ref` mandatory per fact, with `source_type`/`uri` `min_length=1`
  (explicit provenance, never empty).

### `application/mappers/brand_fixture_mapper.py`

`map_brand_fixture(fixture) -> tuple[Brand, BrandSnapshot, tuple[ApprovedFact, ...]]`:
- `Brand` with `new_id()` + `utc_now()`.
- One `ApprovedFact` per fixture fact (`status=APPROVED`, `superseded_by=None`,
  `deleted_at=None`, fresh `FactId`).
- `BrandSnapshot` with `version=1`, `approved_fact_ids` = the exact ids of the
  returned facts, and `language`/`locale`/`script` derived from
  `ContentLanguageContext` `.value`s (this mapper is the "caller" the
  `BrandSnapshot` docstring refers to).
- Pure in-memory — no SQLite, no mutation.

### `resources/fixtures/brightsmile.json`

One complete demo fixture (BrightSmile Dental, BHS/Latin) with 3 facts,
1 audience, 1 service, 2 restrictions, full voice + visual identity. Validates
and maps end-to-end.

### `Restriction` extension

**Not extended.** The fixture needs only `description`, so
`domain/brand/value_objects.py` was left untouched (contract: don't add fields
"za svaki slučaj").
