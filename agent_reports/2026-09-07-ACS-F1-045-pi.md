## Fix round (Claude review F1, commit `c62e758`)

Reviewer je tražio jednu ciljanu izmjenu: telefon-pattern je imao SVA tri
separatora opcionalna, pa je goli 8-10-cifreni niz (`12345678`) lažno prolazio
kao "kontakt info" i izbjegavao `unsupported-number`. Ispravljeno:
`\d{2,3}[\s\-\./]?\d{3}` → `\d{2,3}[\s\-\./]\d{3}` (BAR jedan separator
između prve dvije grupe obavezan), u YAML + test `_rules()` helperu. Dodat
regression test `test_bare_long_number_without_separator_is_not_contact_info`.

Doslovan dokaz (isti tekstovi kao reviewer):

```text
'Pozovite 065 123 456.'  -> NON_FACTUAL ()
'Kontakt: 033/123-456'   -> NON_FACTUAL ()
'Tel +387 61 123 456.'   -> NON_FACTUAL ()
'Imamo 12345678 klijenata.'  -> UNSUPPORTED ('unsupported-number',)
'Imamo 123456789 klijenata.' -> UNSUPPORTED ('unsupported-number',)
'Imamo 1234567890 klijenata.'-> UNSUPPORTED ('unsupported-number',)
```
