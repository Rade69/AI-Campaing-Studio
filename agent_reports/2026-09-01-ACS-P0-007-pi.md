## Implementation summary

### P0.20 — jobs (framework-neutral)

- `models.py`: `JobStatus` (PENDING/RUNNING/CANCELLING/CANCELLED/SUCCEEDED/FAILED)
  and frozen `JobState` (id, job_type, status, progress_current, progress_total,
  phase, message, error_code?, error_message?, started_at?, finished_at?).
- `events.py`: `JobEventType` (all 8 values) and frozen `JobEvent`
  (job_id, event_type, timestamp, payload).
- `cancellation.py`: thread-safe `CancellationToken` (`threading.Event`) +
  `CancellationError`. No Qt.
- `manager.py`: `JobManager` over `ThreadPoolExecutor` with
  `submit(job_type, callable)`, `get_state(job_id)`, `cancel(job_id)`,
  `subscribe(callback)->unsubscribe`, `shutdown(wait=...)`.
  - cancel-aware callable declares a `token` param (or `**kwargs`); manager
    detects it via `inspect.signature` and passes `token=...`.
  - `CancellationError` → `CANCELLED`; any other exception → `FAILED` with
    `error_code` (AppError code or exception class name) + `error_message`.
  - State transitions use immutable snapshots via `dataclasses.replace` under
    a lock; events are emitted outside the lock.
  - `cancel` on PENDING → straight `CANCELLED`; on RUNNING → `CANCELLING`
    + `CANCELLATION_REQUESTED` (emitted before `request_cancel` so the event
    order is deterministic).

### P0.21 — presentation (framework-neutral)

- `state.py`: `AppRuntimeState` + `StartupStatus` enum. No selected
  campaign/post/plan.
- `ui_models.py`: frozen `NotificationUiModel` + `ProviderStatusUiModel`
  + `NotificationLevel` enum.
- `contracts.py`: `PresentationFacade` protocol with the six foundation
  methods. No Qt/Flask/webview imports.

### P0.22 — bootstrap

- Extended the existing `Bootstrap` class (no parallel `FoundationContainer`).
  Fields: settings, paths, logger, translator, platform_registry,
  provider_registry, model_registry (alias to provider_registry), secret_store,
  database_connection, migration_runner, migrations_dir, job_manager.
- Build sequence exactly per contract: Settings → AppPaths → logging →
  Translator → PlatformRegistry → AIProviderRegistry → SecretStore selection
  (environment→EnvironmentSecretStore, production→KeyringSecretStore; no secret
  read) → `create_connection` → `run_migrations` → JobManager.
- Registries/translator/migrations use `paths.resources_dir` (so
  `resource_dir_override` works and temp-path tests are isolated).
- `run_health_check(bootstrap) -> dict[str, str]` + `build_failed_health_result()`.

### P0.23 — health check

- `main.py`: `run_health_check_cli()` prints sorted JSON and returns 0/1.
- `scripts/health_check.py`: thin wrapper calling `run_health_check_cli()`.

## Fix round 1 (2026-09-01)

Bug found in `tests/unit/presentation/test_no_gui_imports.py`: the helper
returned only top-level module names (`split(".")[0]`), so the
`_FORBIDDEN_PREFIXES = ("ai_campaign_studio.infrastructure",)` check could
never match — the infrastructure-boundary half of the guard was a no-op.

Fix: rewrote the helper to return full module names (`from X import Y` counts
as `X.Y`, relative imports resolved against the presentation package) and
added two self-tests proving the guard actually catches forbidden imports
(and allows clean ones). Adversarial proof with a real file probe: a
forbidden infra import was temporarily added to `presentation/state.py`,
the guard test FAILED (caught the exact dotted path), then the import was
removed and the test PASSED. See
`agent_reports/2026-09-01-ACS-P0-007-fix-round1-pi.md`.
