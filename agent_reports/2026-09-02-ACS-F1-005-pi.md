## Implementation summary

### `ports/repositories.py`

All 7 `@runtime_checkable` `Protocol` interfaces: `BrandRepositoryPort`,
`FactRepositoryPort`, `CampaignRepositoryPort`, `ContentRepositoryPort`,
`VisualRepositoryPort`, `RevisionRepositoryPort`, `TelemetryRepositoryPort`.
Framework-neutral — no `sqlite3`/infrastructure imports. The 4 detailed ones
match plan §16 exactly; the other 3 use reasonable signatures documented in
docstrings (`get_*` return `X | None`, `list_*` return `tuple[...]`).
`TelemetryRepositoryPort.record_event(event: dict[str, Any])` is interface-only
(no adapter, no migration).

### `resources/migrations/0001_brand_facts.sql`

`brands`, `brand_snapshots` (value-object graph as JSON text columns:
voice/audiences/services/visual_identity/restrictions), `approved_facts`
(provenance flattened into columns), and `brand_snapshot_facts` join table.

**Deviation from contract DDL (documented):** `brand_snapshot_facts` has an
extra `position INTEGER NOT NULL` column (PK stays `(snapshot_id, fact_id)`),
so `BrandSnapshot.approved_fact_ids` (a `tuple`, i.e. ordered) round-trips
without losing order — required by the "no data loss on round-trip"
acceptance.

### SQLite adapters

`SqliteBrandRepository` / `SqliteFactRepository` take a `sqlite3.Connection`
(caller passes `SqliteUnitOfWork().connection`). `save_*` are idempotent via
`INSERT ... ON CONFLICT(id) DO UPDATE`; `save_snapshot` re-writes the join
rows so a re-save never duplicates. JSON columns serialize with
`dataclasses.asdict` and deserialize by reconstructing the value objects
(their `__post_init__` coerces list→tuple, keeping round-trip symmetric).
`list_snapshot_facts` orders by `position`.
