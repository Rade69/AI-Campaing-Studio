## 1. Odmah: Odluka

`PillowRenderer._draw_cta` je sada word-wrap-aware: prije crtanja, CTA tekst se propušta kroz **postojeću** `_wrap_text` funkciju sa `max_width = cta_w - 2 * _CTA_PADDING_X` (540 - 48 = 492 piksela). Svaki wrapped red je garantovano širine ≤ 492px, tako da `(w - tw) // 2` centriranje NIKAD ne može ići negativno. Dugme ZADRŽAVA fiksnu širinu (540px) i MINIMALNU visinu (84px) za kratak tekst; raste po visini za višeredni tekst. Nema izmjene `RenderResult.status` logike (CTA overflow NE emituje `LAYOUT_VALIDATION_ERROR` — namjerno van scope-a po contractu).

2 nova testa (reprodukcija buga + regresija) + 12 postojećih testova = **14/14 PASS**. Gate zelen: pytest **926/926**, ruff/mypy clean.

## 3. Uzrok buga i fix

### 3.1. Prije (bug)

```python
# PillowRenderer.render(), CTA sekcija, original
cta_w, cta_h = 540, 84
# ...
_draw_cta(
    draw, request.content.cta, cta_x, cta_y, cta_w, cta_h,
    request.layout_spec.cta_style, cta_font,
)

# _draw_cta(), original
bbox = draw.textbbox((0, 0), text, font=font)
tw = bbox[2] - bbox[0]
draw.text(
    (x + (w - tw) // 2, y + (h - th) // 2 - bbox[1]),
    text, fill=(255, 255, 255), font=font,
)
```

Kad je `text = "Zakažite konsultaciju i otkrijte mogućnosti za vaš osmeh."` (57 karaktera, `tw > 540`):
- `(w - tw) // 2 = (540 - 800) // 2 = -130`
- `x + (-130) = 80 - 130 = -50` — početna X koordinata teksta je **-50** (van platna)
- Pillow crta tekst počevši od X=-50; prvih 50 piksela ide na negativne X koordinate, sljedećih 50+ na X ∈ [0, ...] — dakle tekst se pojavljuje na lijevoj ivici platna, odsječen.

### 3.2. Poslije (fix)

```python
# PillowRenderer.render(), CTA sekcija, fix
cta_w = 540
cta_lines = _wrap_text(
    request.content.cta, cta_font, cta_w - 2 * _CTA_PADDING_X
)
cta_line_h = int(_CTA_FONT_SIZE * _LINE_HEIGHT)
cta_h = max(
    _CTA_MIN_HEIGHT,
    len(cta_lines) * cta_line_h + 2 * _CTA_PADDING_Y,
)
# ...
_draw_cta(
    draw, cta_lines, cta_x, cta_y, cta_w, cta_h,
    request.layout_spec.cta_style, cta_font,
)

# _draw_cta(), fix — radi sa list[str] umjesto str
for i, line in enumerate(lines):
    bbox = draw.textbbox((0, 0), line, font=font)
    tw = bbox[2] - bbox[0]
    line_x = text_x_start + ((text_x_max - text_x_start) - tw) // 2
    # `text_x_max - text_x_start` = cta_w - 2*PADDING_X, pa je `tw` (koji
    # je <= cta_w - 2*PADDING_X po _wrap_text-ovom ugovoru) garantovano
    # <= text_x_max - text_x_start. Dakle, `(text_x_max - text_x_start)
    # - tw >= 0` UVIJEK, pa je `line_x >= text_x_start` UVIJEK.
    line_y = text_block_y + i * line_h - bbox[1]
    draw.text((line_x, line_y), line, fill=..., font=font)
```

`_wrap_text` GARANTUJE: svaki `line` u `cta_lines` je širine `<= cta_w - 2 * _CTA_PADDING_X` (492px). Stoga, u `_draw_cta`, `tw <= text_x_max - text_x_start` UVIJEK vrijedi, pa `(text_x_max - text_x_start) - tw >= 0` UVIJEK, pa `line_x >= text_x_start = x + _CTA_PADDING_X` UVIJEK. NEMA puta do `(w - tw) // 2 < 0`.

### 3.3. Zašto je originalni kod propust

Headline putanja u `render()` (isti fajl, linija ~400-450) već ima word-wrap (`_wrap_text` + `LAYOUT_VALIDATION_ERROR` ako overflow). CTA putanja je imala ČISTU pretpostavku da tekst uvijek stane u 540px — nema `_wrap_text`, nema overflow provjere. Svi ACS-F1-033 test CTA tekstovi su bili kratki (`"Zakažite konsultaciju"`, `"CTA"`, `"Zakažite"`) — nijedan dovoljno dug da prevaziđe 540px. Tek live A19 provjera sa stvarnim DeepSeek API odgovorom (57-karakterna rečenica) je otkrila gap.

## 6. Ključne odluke

1. **REUSE postojeće `_wrap_text`, NE nova wrap funkcija.** Contract eksplicitno: "koristi POSTOJEĆU `_wrap_text` (nema duplirane wrap logike)". `_wrap_text` je već korišten za headline wrap, ima istu potpis `(_wrap_text(text, font, max_width) -> list[str])`. Samo pozivam sa drugim argumentom.
2. **`_draw_cta` potpis: `text: str` → `lines: list[str]`.** Caller (`render()`) je JEDINI pozivalac, ažuriran u istom commitu. Tri stila (SOLID/OUTLINE/TEXT) iteriraju `lines` sa `for i, line in enumerate(lines)`.
3. **Dugme RASTE PO VISINI, ne po širini.** Širina je fiksna na 540px (pozicija u layoutu); visina se računa kao `max(_CTA_MIN_HEIGHT, len(cta_lines) * line_h + 2 * _CTA_PADDING_Y)`. Za kratak tekst, `len(cta_lines) == 1` → visina = `max(84, 1*43+40) = max(84, 83) = 84`. Za dugačak tekst, visina raste. Y pozicija (`int(h * 0.85)`) se NE MIJENJA, pa dugme koje naraste preko 84px MOŽE ići van donje ivice platna — ALI to je sljedeći dizajn razgovor (van scope-a po contractu).
4. **Vertikalno centriranje unutar dugmeta.** Ako `total_text_h + 2 * _CTA_PADDING_Y <= h` (npr. dugme 84px, tekst visine 43, padding 20+20=40, ukupno 83 ≤ 84), tekst se centrira vertikalno. Inače, tekst počinje na `y + _CTA_PADDING_Y` i ide prema dolje.
5. **Nema `LAYOUT_VALIDATION_ERROR` za CTA overflow.** Contract: "namjerno van scope-a, potvrditi da `RenderResult.status` logika za headline overflow ostaje jedini izvor tog statusa". Headline overflow detekcija je u `render()` PRIJE CTA sekcije, koristi `len(head_lines) > max_lines` provjeru. CTA NE dodaje taj status.
6. **`_CTA_PADDING_X = 24`, `_CTA_PADDING_Y = 20`.** Manji od headline margina (80/80) jer dugme izgleda kao realan UI element, ne banner.

## 9. Notes / lessons

1. **CTA dugme raste po visini, ne po širini.** Za dugačak tekst, dugme MOŽE preći donju ivicu platna (`int(h * 0.85) + cta_h > h` ako je tekst 5+ redova). Contract: "Dugme RASTE PO VISINI kad tekst zahtijeva više od jednog reda" — ovo je PRIHVAĆENO. Ako bude realan problem, sljedeći task: ili smanjiti font, ili povećati `cta_y` za wrap CTA, ili dizajnirati alternativni "split CTA" pattern.
2. **Nema `LAYOUT_VALIDATION_ERROR` za CTA.** A19 live provjera je pokazala da dug CTA TEKST JE VIZUELNI PROBLEM (odsječen), ne "validation" problem (predugačak sadržaj). Renderer GA MOŽE FIX-ati (word-wrap), tako da nema potrebe za signalom "fix me". Headline overflow NEMA rješenje u rendereru (tekst se ne može skratiti bez promjene sadržaja) → to je `LAYOUT_VALIDATION_ERROR`.
3. **Test gap u ACS-F1-033.** Svi CTA testovi su imali kratak tekst (`"Zakažite"`, 8 karaktera). Za renderering biblioteku, test coverage dužine teksta treba biti: min (1 char), realistic (10-30), max (>50). Dodao sam `test_long_cta_text_wraps_instead_of_clipping` kao regression guard za sljedeću refaktor.
4. **Pillow `getlength` je ista mjera kao `textbbox` width.** `_wrap_text` koristi `font.getlength(line)` (brže), `_draw_cta` koristi `draw.textbbox((0,0), line, font=font)[2] - [0]` (tačnije, uključuje i padding oko glypha). Razlika je ~1-2 piksela po redu, NE dovoljno da probije padding marginu. Ako postane problem, refaktor na jednu mjeru.
