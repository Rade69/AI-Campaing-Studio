## Implementation summary

- **`subprocess_runtime/ipc.py`** — line-delimited JSON-RPC: `PlaywrightRequest`
  (request_id, url, timeout, max_bytes, browser, `allowed_ports`,
  `dns_overrides`) i `PlaywrightResult` (ok / status_code / final_url /
  content_type / body_b64 / headers / error_code / error_message). Body putuje
  base64-encoded. `allowed_ports`/`dns_overrides` su SERIJALIZABILNA zamjena za
  callable `dns_resolver` (ne može preko procesne granice).
- **`subprocess_runtime/playwright_worker.py`** — worker entry
  (`python -m ...`): jedan dugovječni headless Chromium, SERIJSKI niz
  zahtjeva sa stdin/stdout. Per-request hardening: svježi `BrowserContext`
  (`service_workers="block"`), `context.route("**/*")` koji re-validira svaki
  in-page request kroz `UrlSafetyPolicy`, `page.content()` (renderirani DOM,
  post-JS — svrha fallback-a) umjesto sirovog `response.body()`. Full cleanup
  (`context.close()`) u `finally`. Playwright se importuje LAZY uz
  `# type: ignore[import-not-found]` — `mypy src` mora biti zelen i u CI gdje
  playwright nije instaliran (nije hard dependency, `renderer-spike` extra).
- **`infrastructure/web_ingestion/playwright_fetcher.py`** — `PlaywrightWorker`
  (parent-side subprocess manager: idempotent `start`, `stop`, `restart`,
  crash recovery preko `poll()`, parent-side watchdog timeout → terminate +
  respawn) + `PlaywrightFetcher` (implementira postojeći `HttpFetcherPort`,
  top-level SSRF validacija parent policy-jem, mapira `PlaywrightResult` →
  `FetchResult`). `_spawn` eksplicitno PINUJE `PYTHONPATH` na `src` root
  (workflow §13 `.pth` zamka — potvrđeno da `.pth` pokazuje na OBRISANI
  worktree `ACS-S2-013`).
- **`js_render_detector.py`** — heuristika 0/1/2+ markera (React/Vue/Angular
  root, `__NEXT_DATA__`/`__NUXT__`/`__INITIAL_STATE__`, `<script type=module>`,
  `<link rel=modulepreload>`, `<noscript>`+`<script>`), empty-body shell
  (zahtijeva `<head>`), non-HTML content-type short-circuit. `has_spa_shell()`
  za `page_classifier`.
- **`page_classifier.py` (infrastructure)** — URL path prioritet (reuse
  postojećeg `UrlClassifier`), non-HTML content-type refinement, SPA-shell
  override (client-routed `/blog/x` → HOME, ne BLOG).
- **`application/ingestion/page_classifier.py`** — tanki use-case wrapper
  (`ClassifyPage` + `PageClassifierPort` Protocol), application sloj NE

## OUT_OF_SCOPE_FINDINGS

1. **Kontrakt §1 navodi `ports/repositories.py` kao "PROŠIRITI: HttpFetcherPort"
   — GREŠKA u kontraktu.** `HttpFetcherPort` živi u `ports/web_ingestion.py`
   (S2-G1), i kontrakt §8 eksplicitno zabranjuje izmjenu njegovog potpisa.
   `PlaywrightFetcher` implementira postojeći port BEZ izmjene — nijedan
   `ports/*` fajl NIJE diran. (Koordinator: ispraviti allowed_paths u
   kontraktu ili ignorisati — nema uticaja na kod.)
2. **`context.route` NE presreće redirect hop-ove top-level navigacije**
   (live-reprodukovano: `302 → 127.0.0.1` je stigao do servera; route je vidio
   samo top-level URL). Kontrakt §5 "redirect chain → blocked" je ispunjen
   DRUGAČIJIM mehanizmom: pre-navigaciona redirect-chain validacija u workeru
   (`_redirect_unsafe_reason`, `requests` + `allow_redirects=False` + ručno
   praćenje hopova kroz isti `UrlSafetyPolicy`). Ovo je defense-in-depth
   kompenzacija; ostaje uzak TOCTOU prozor (browser ponovo prati redirect —
   isti nivo kao G3 koji ne pinuje IP). Ako review traži strože, follow-up:
   route handler + `route.fetch()` manual redirect.
3. **`response.body()` cap je post-hoc** (kontrakt §2 pseudo-kod). Worker
   vraća renderirani `page.content()` (potreban za G-WI-BROWSER "renderirani
   HTML"), a cap se primjenjuje na `len(body.encode())` poslije serijalizacije
   DOM-a. Playwright sync API ne nudi streaming cap bez route interception;
   za ovaj opcioni fallback je prihvatljiv kompromis. `page.content()` umjesto
   `response.body()` je NAMJERNO (sirovi `response.body()` SPA shell-a bi bio
   isti kao HTTP-only — ne ispunjava §5).
4. **`stderr=DEVNULL`** u worker subprocess-u (kontrakt §2 primer `stderr=PIPE`).
   Namjerno — Chromium piše mnogo na stderr, a PIPE bez čitača = deadlock
   rizik; crash recovery ide preko `poll()` + stdout EOF. (Dijagnostika je
   žrtvovana za bezbjednost; može se dodati ring-buffer stderr reader u
   follow-up-u.)
