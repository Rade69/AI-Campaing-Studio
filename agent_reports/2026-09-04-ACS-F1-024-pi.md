## Implementation summary

### 1. `_resolve_provider` postaje fallback petlja

Umjesto "uzmi jedan kod pa mu čitaj ključ", sada iterira kroz SVE konfigurisane
kodove u prioritetnom redoslijedu i vraća prvi sa stvarnim (ne-praznim) ključem:

```python
ordered_codes = _ordered_configured_codes(configured_codes)
if not ordered_codes:
    return None, None
last_code = ordered_codes[-1]
for code in ordered_codes:
    config = next((c for c in configs if c.provider_code == code), None)
    if config is None or not config.credential_ref:
        last_code = code
        continue
    try:
        api_key = self._bootstrap.secret_store.get_secret(config.credential_ref)
    except Exception:
        last_code = code
        continue
    if api_key:
        return code, api_key
    last_code = code
return last_code, None
```

- Nijedan konfigurisan → `(None, None)` (NO_PROVIDER_CONFIGURED, netaknut).
- Svi konfigurisani ali nijedan nema ključ → `(last_tried_code, None)`
  (PROVIDER_KEY_MISSING, sada istinito — svi su probani).
- Prvi sa ključem → `(code, key)` odmah.

### 2. Dizajn odluka — `_ordered_configured_codes` + import `_PROVIDER_PRIORITY`

`pick_configured_provider` vraća SAMO jedan kod, a `provider_adapter_factory.py`
je u `infrastructure/` = `forbidden_path` (ne smijem dodati javnu list-funkciju
tamo). Da NE bih duplirao prioritet (dva source of truth rizikuju divergenciju),
u bridge sam dodao lokalnu helper funkciju `_ordered_configured_codes` koja
IMPORTUJE `_PROVIDER_PRIORITY` iz factory-ja kao jedini source of truth:

```python
from ai_campaign_studio.infrastructure.ai.provider_adapter_factory import (
    _PROVIDER_PRIORITY,
    build_text_generation_adapter,
)
```

`_ordered_configured_codes` vraća priority kodove po `_PROVIDER_PRIORITY`
redoslijedu (OPENAI > ANTHROPIC > GOOGLE), pa sve preostale konfigurisane kodove
u originalnom redoslijedu — identična logika kao `pick_configured_provider`, ali
vraća SVE kandidate. Import private simbola je namjeran i dokumentovan (ne želim
duplirati prioritetnu listu; `pick_configured_provider` import uklonjen jer se
više ne koristi).
